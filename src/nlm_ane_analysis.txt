// ANE/NPU Feasibility Analysis
// ==============================
// Apple Neural Engine (ANE) is optimized for matrix multiplication, convolutions,
// and element-wise operations on MTLBuffers. NLM Denoising relies on:
//
//   1. Patch-based SSD computation (local window similarity)
//   2. Exponential weighting (exp(-d²/h²))
//   3. Weighted accumulation
//
// ANE Strengths (via Core ML / BNNS):
//   - Matrix multiply (pixel × neighborhood weight matrix): ANE's primary op.
//     The NLM patch comparison can be formulated as a 2D convolution of squared
//     differences with a patch kernel → ANE-conv can accelerate this.
//   - Element-wise exp via MPS (Metal Performance Shaders): MPS can batch
//     exp() operations on GPU/ANE.
//
// ANE Limitations:
//   - No general-purpose compute. ANE only executes specific ops compiled into
//     a Core ML model (.mlmodelc). Runtime model compilation adds latency.
//   - Works best on quantized (int8/fp16) data. NLM precision needs fp32 in
//     the weighting accumulation.
//   - Round-trip: CPU → ANE → CPU has overhead; ANE benefits larger images.
//
// Recommended Hybrid Approach (future work):
//   1. Patch difference map: Use MPS Convolution (GPU/ANE) to compute squared
//      differences for all search-window offsets in one pass.
//      → Convolution kernel = ones(patch_size, patch_size) / patch_count.
//   2. Weighting: MPS exp() on GPU (ANE not needed here; GPU float precision OK).
//   3. Accumulation: CPU or GPU gather.
//
// Current architecture: Multi-resolution (--fast) and Metal GPU already
// deliver 63-79× vs naive, serving as practical ANE alternatives.
